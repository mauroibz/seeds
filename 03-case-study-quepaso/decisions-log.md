## Settled — product (owner, 2026-07-06)

| # | Decision | Choice | Rationale |
|---|---|---|---|
| P1 | Moderation MVP | Flag button + admin queue; auto-hide at 3 distinct-user reports | Legal baseline for photo UGC without pre-moderation bottleneck |
| P2 | Pin/aggregation model | One pin per report; visual clustering; "nearby pins" panel; no shared place entity | Address canonicalization is hard and error-prone; social dedup + later admin merge tool |
| P3 | Visibility | Public-only; states = published/hidden/deleted; no drafts/unlisted | Matches "public record of the city"; drafts addable later as a status value |
| P4 | Photos & EXIF | Strip all EXIF from public images (client re-encode); retain full original EXIF + hash **privately** (admin-only) for anti-spam validation | "Anonymity in public images, but keep original metadata to validate we're not being spammed" — owner's explicit hybrid |
| P5 | Anonymity semantics | Hidden from public; author link kept internally; admins can see it; UI discloses this honestly | Enables bans/rate-limits/legal compliance; consistent with P4 |
| P6 | Resolution flow ("mark as solved") | Deferred — no verified-resolution flow in MVP; schema keeps `status` headroom (`'resolved'` reserved). *Amended 2026-07-06: the expiry half was un-deferred and designed as P8; only verified resolution remains deferred.* | Owner chose least scope initially, then revisited expiry |
| P7 | Anti-gaming for likes | Accepted v2 gap; MVP has only per-user daily rate limits | From brief; schema keeps likes-as-rows + timestamps + private metadata as raw material |
| P8 | Activity lifecycle (expiry) — **in MVP** | Sliding timer on `expires_at`: 14-day window at launch (tunable); non-author comment/photo re-arms fully, like adds 48h, author self-bumps add nothing; state derived at read time (no cron): `active` → `fading` (last 24h, amber pulse + keep-alive banner) → `dormant` (ghost pin, out of feed, revivable by any new interaction) | Owner's Reddit-style expiry idea, reconciled with the permanence goal: pins never disappear, they decay visually and in ranking. | P12 | UX/UI polish (Sprint C) | Map centers on the user on load **only if within `ROSARIO_MAX_KM` (50 km)** of the launch city, else stays on the Rosario view (never opens on an empty map). Topbar is full-bleed edge-aligned. **Initial viewport fetch is driven imperatively from an effect (map bounds), not react-map-gl's `onLoad`/`onIdle`** — those can fire before the React handlers attach and never replay, which was the real cause of the "feed empty until you pan" bug | Owner-flagged UX issues 2026-07-19 + expert additions; owner chose locate-with-Rosario-fallback and the `⋮` menu. The load/idle-event unreliability is a react-map-gl gotcha worth remembering |
| P13 | Social UX/UI pass (Sprint D) | Turn the "data-dashboard" feel into a social/gossip surface: (1) the left rail becomes the single browsing surface with a **Cerca · Nuevos · Populares** segmented control + tag search, so **Novedades is folded into the map** (no separate screen; `/novedades` renders the map home with the rail in feed mode, `?tag=` deep-links a filter); (2) the pin panel is **photo-first** (hero cover) with a condensed header, a **sticky chat-style comment composer**, a collapsed "Otros pines cerca", and an animated like — reads like a thread, not a form; (3) posting is invited by a **Waze-style warm "+" FAB** on the map's lower-left and a **single-sheet composer** (location defaults to map centre; the **color+icon "chapita" stays the hero** with a live preview + keyword smart-suggest that only ever emits valid keys); (4) one **warm accent** token + restrained motion (spring panels, heart-pop, hover-lift, FAB breathe), all `prefers-reduced-motion`-safe; (5) warmer es-AR copy on empty states/CTAs. **Presentation-layer only — no migration/view/RPC/query change, so the anonymity boundary is untouched (N/A).** | Owner request 2026-07-20 (energetic + social, but **no emoji/confetti**; the chapita is core branding and must stay prominent; Waze-style +; fold Novedades into the rail). Extra sprint before launch, same spirit as B/C |
| P14 | Map "feel alive" pass (Sprint E) | Make the map read as a lively, legible surface rather than a few blue blobs: (1) **category glyph on every teardrop** — a white lucide glyph (the pin's `icon`) rendered on the pin head via a second `pins-glyph` symbol layer stacked on the colored teardrops; sprites are generated into the *same canvas geometry* as the teardrop (`scripts/gen-brand-assets.mjs`, `public/map/glyph-*.png`) so both layers share one anchor/size and align at every zoom (resolves the Sprint-D W4 deferral). Owner chose **zoom-to-fit then mini-list** for cluster taps. Extra sprint before launch, same spirit as B/C/D. Real content density is still a launch seeding task, not code |
| P11 | Branding & visual identity (Sprint B) | Realized `mood.png` as the shipped brand: blue tokens (`#1E40AF`/`#3B82F6`/`#0F172A`/`#F8FAFC`) via shadcn semantic vars, **Poppins** headings + **Inter** body, cursive **quepaso** logo generated from the Pacifico outline font (not pixel-identical to the moodboard — self-serve, owner-approved). **Light is the default theme with a persisted dark toggle** (`next-themes`). Rules in `docs/brand-guide.md` | Owner request 2026-07-19 before the production launch. Owner picked light-default over the moodboard's dark-default note; logo via script-font approximation over blocking on a designer. The pin category palette stays separate from brand tokens |
| P15 | Shareable pins (Sprint F) — link format + share CTA | Make pins easy to share, chiefly to X/Twitter. (1) **Public URL is a base62 encoding of the pin's UUID** — `/p/{22-char}` instead of `/p/{36-char uuid}` (`lib/pin-link.ts`, `encode/decode/pinPath`); the map is lossless/bijective (BigInt, no lookup table, no collisions) and lives **only at the URL layer** — internals stay raw UUIDs. `decodePinId` returns a raw UUID untouched, so **legacy `/p/{uuid}` links (and cached OG fetches) keep resolving**. Decode at the route boundary (`app/p/[id]/page.tsx` + `/og`) and in the map's shallow routing (`map-view.tsx`); every link builder emits `pinPath()`. (2) The pin panel's share affordance becomes a **CTA** (`pin-panel.tsx`): a native OS share sheet on devices with `navigator.share` (mobile → X/WhatsApp/IG…), else a dropdown with **"Compartir en X"** (pre-filled `intent/tweet`, text = pin title, `hashtags=QuePaso,Rosario`) and **"Copiar link"**. **Presentation/URL-layer only — no migration/view/RPC/query change; anonymity boundary untouched (N/A).** | Owner request 2026-07-21: Twitter-first distribution needs a clear share CTA + shorter links. Owner chose the native-sheet + X + copy shape and **base62 UUID encoding** (no schema change, no third-party/short-domain). Honest caveat recorded: on X, link length doesn't affect the tweet (every URL is wrapped to a 23-char `t.co`); base62 is a prettiness win for WhatsApp/IG/verbal, the button + pre-filled tweet is the real lever. A dedicated short **domain** (`qpso.ar`-style, needs owner + NIC.ar) is deliberately out of scope |

## Settled — technical (delegated, 2026-07-06)

| # | Decision | Choice | Alternatives considered |
|---|---|---|---|
| T1 | Frontend | Next.js (App Router) + TS + Tailwind + shadcn/ui on Vercel | Vite SPA (no SEO), SvelteKit (smaller ecosystem) |

| T5 | API layer | No custom server: RLS + security-definer views + SQL RPCs via PostgREST | Next.js API routes / Edge Functions (kept as escape hatch) |
| T6 | Feed freshness | Polling + refetch-on-focus (~30 s) | Supabase Realtime (later drop-in) |
| T7 | Anonymity enforcement | DB views null author fields; real id never leaves Postgres | Frontend filtering (rejected: not a boundary), separate shadow tables (overkill) |
| T8 | Region/hosting | Supabase `sa-east-1`, Vercel Hobby | — |
| T9 | Likes scope | Pin-level only (no comment likes) in MVP | — |
| T10 | Lifecycle implementation | `expires_at` column moved by existing insert triggers; state derived at read time via `activity_state()`; no cron/batch jobs | pg_cron batch state flips (more moving parts, stale states between runs) |
